# Android build and security notes

## What the Android workflow does

- Installs the pinned Three.js 0.128.0 npm dependency and copies it into `www/vendor/three.min.js`.
- Builds the Capacitor Android wrapper from the `www` directory.
- Prints the generated Android manifest permissions and fails if selected sensitive permissions are declared.
- Builds a debug APK and records its SHA-256 checksum.
- Uploads the APK, checksum, and generated Android manifest as a GitHub Actions artifact.

## Network use

The game HTML loads Three.js from the local `vendor/three.min.js` file. This removes the game's previous runtime dependency on cdnjs for the 3D engine. The build itself still downloads npm and Android build dependencies.

## Permissions

The workflow checks the generated manifest for a list of sensitive permissions, including camera, microphone, location, contacts, SMS, phone, boot receiver, and broad storage access. Review the printed permission list in every build; a passing check is not a complete security audit.

## APK signing

The workflow produces a debug APK, which Android signs with the temporary debug key generated by the build environment. This is suitable for testing, not as a durable Play Store release identity. A release APK must be signed with a private keystore controlled by the app owner. Never commit a keystore or its passwords to this repository or share them in chat.

## Audit limitations

Automated source and manifest checks cannot prove that an app is malware-free. They do not replace full code review, dependency review, runtime testing on a test device, or independent antivirus scanning. The app should only be installed from a build you trust, and Play Protect should remain enabled.
